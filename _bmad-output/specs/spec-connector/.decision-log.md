## 2026-06-13 — Update v2: MCP backend layer + HA backbone (brainstorm-driven)

**Source:** `brainstorming-session-2026-06-13-1.md` — Assumption Reversal + Cross-Pollination + Constraint Mapping techniques. 11 insights, 5 constraints mapped (4 imaginary, 1 real resolved by existing Level 1/Level 2 design).

**Core finding:** The 2026-06-11 spec was built on an unverified assumption — "nothing in the market does what we want." Research in this session confirmed: Garmin has 3 community MCP servers (same `garminconnect` lib), Google Calendar has official Google MCP server, HA has official MCP server integration (2024.10+) with native WebSocket events.

**Reversed decision from 2026-06-12:** The non-goal "MCP-style per-operation tool registration" is preserved — the LLM-facing 2-tool surface is kept. What changes is the *backend*: Python connector classes for Garmin and Calendar are replaced by MCP server processes. The Level 1/Level 2 gateway pattern is retained and is architecturally superior to market MCP gateways (which use lazy loading; YANA's meta-tool abstraction does not exist in published form).

**Changes:**
- CAP-4 updated: backend is now either MCP server reference (preferred) or Python class (fallback). Same LLM-facing interface either way.
- CAP-7 added: Home Assistant as backbone for device connectors and push-notification events.
- Constraints: added MCP-first rule; Garmin and Calendar MUST use MCP backends; credentials belong to backend process; MCP servers are local only.
- Non-goals: replaced "MCP-style tool registration" nuance with explicit exclusion of custom Python for Garmin/Calendar; added HA event bus non-goal (HA handles it); added connector versioning as explicit non-goal.
- Assumptions updated: Python MCP SDK, HA 2024.10+, test-driven migration.
- New companion: `migration-plan.md` (test-driven 5-phase migration from Python backends to MCP servers).

**Self-validate Pass 1 — Coherence:** CAP-1 through CAP-7 each have intent (WHAT) and testable success. No HOW in intents. Constraints rule out real choices (Python for Garmin/Calendar, cloud MCP servers, custom event polling). Non-goals explicit (7 listed). Success signal is demonstrable. IDs stable — CAP-1 to CAP-6 preserved, CAP-7 new.

**Pass 2 — Preservation:** All 11 brainstorm insights accounted for:
